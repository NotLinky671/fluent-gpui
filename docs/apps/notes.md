# 便签集成验证应用（fluent-notes）

状态：应用源码位于 [`crates/fluent-notes`](../../crates/fluent-notes)，已完成一轮自动化测试与真实窗口操作检查。
本页记录范围、当前能力核对、可重复的手工验收清单与已知限制；实际运行结果单独记在
[验证记录](../validation/notes-app-2026-11-03.md)。Gallery 继续负责单组件外观矩阵，本应用只负责跨组件的真实操作流程。

## 目的与边界

- 在真实操作流程中组合 `TextInput`、`Textarea`、`Field`、`Button`、`MenuDropdown`、`Popover`、`Tooltip`、
  `Checkbox` / `Switch` / `Radio`、`Divider`、`Badge` 与 `FluentRoot`，检查状态归属、焦点、键盘和重绘行为。
- 只使用 `fluent-ui` 的公开导出和 `fluent_ui::gpui` / `fluent_ui::gpui_base` 重导出的同一份 GPUI 类型；
  不新增组件 API，不为占位伪造组件。
- 不做账号、联网、云同步、Markdown、富文本或持久化。第一版数据只存在于内存，关闭窗口即丢失；界面上有常驻提示。
- 删除确认与“未保存切换”确认已接入 `Dialog` / `AlertDialog`（T-046 已落地），`pending` 状态机不变。

## 运行

```text
cargo run -p fluent-notes
```

可选环境变量（与 Gallery 的验证开关同一思路，不影响普通使用）：

| 变量 | 作用 |
|---|---|
| `FLUENT_NOTES_SMOKE=1` | 启动窗口、等待约 1.5 秒后退出，用于 CI 启动 smoke |
| `FLUENT_NOTES_APPEARANCE=light\|dark\|hc` | 启动主题；缺省使用 `fluent_ui::init` 安装的 light |

PowerShell 例：

```powershell
$env:FLUENT_NOTES_APPEARANCE = "dark"; cargo run -p fluent-notes
```

## 能力核对（2026-11-03，基线 `b438401`）

下表是写应用前对公开 API 与现有测试的核对结果，不代表下面所有交互都已在原生窗口复验。

| 能力 | 核对结果 | 本应用中的用法 | 依据 / 边界 |
|---|---|---|---|
| `FluentRoot` | 可用 | 最外层背景、前景、字体；托管 Tooltip overlay；提供 Tab 遍历 key context | [root.rs](../../crates/fluent-components/src/root.rs)、[focus.md](../subsystems/focus.md) |
| `Button` | 可用 | 保存/取消/新建/删除/属性入口；图标按钮全部带 `tooltip` | `Button::tooltip` 依赖 `FluentRoot` |
| `TextInput` | 可用 | 标题编辑；焦点、IME、选择和光标来自 `InputState` | 本库只负责外壳；点击别处会清焦点 |
| `Textarea` | 可用 | 正文编辑；固定编辑区高度，长文由输入引擎滚动 | 鼠标滚轮在本版 GPUI 快照中不滚动，见已知限制 |
| `Field` / `Label` | 可用 | 标题/正文标签、空标题提示 | 没有错误校验需求，空标题是合法值 |
| `Checkbox` / `Switch` / `Radio` | 可用，受控/非受控两种模式 | 设置里的受控示例；标记为“非受控示例”的控件只用于检查重绘保持 | 非受控值存 window keyed state，默认值只在初始化时使用 |
| `Tooltip` | 可用（Button 路径） | 新建、设置、更多、删除等图标按钮 | 悬停触发；键盘聚焦不显示 Tooltip，见已知限制 |
| `Popover` | 实验性，可用 | 设置浮层与便签属性浮层；`track_focus` 提供焦点交接、Esc 和 Tab 陷阱 | 边缘限位而非翻转；打开时焦点进入面板容器，但容器不作为 Tab 停靠点；Tab 只在面板控件间循环 |
| `Menu` / `MenuDropdown` | 部分实现 | 编辑器“更多”菜单：置顶勾选项、禁用项、分隔线、删除 | 方向键/Home/End/Enter/Space 与禁用跳过已有测试；typeahead 按字符前缀匹配，Tab / Shift+Tab 关闭菜单；item 激活后不会自动关闭，应用在动作中显式关闭；子菜单未实现 |
| `Divider` / `Badge` | 可用 | 分区、内存提示、置顶标记 | `Badge` 前景对比缺陷已按对比度映射修复，见[修复记录](../validation/badge-contrast-2026-11-03.md)；应用仍不依赖它表达未保存状态 |
| `Dialog` / `AlertDialog` | 已实现 | 删除用 `AlertDialog`（必选动作、无 Esc/scrim 关闭）；未保存切换/新建用 `Dialog`（Esc/scrim 视为留在当前） | 两个对话框常驻挂载、由 `pending` 受控驱动 |
| `Tabs` / `TabList` | 可用（基础实现） | 不接入；设置分区仍是单列 | 组件已实现，应用没有改造成标签页；接入点见文末 |
| `Sheet` | 可用（基础实现） | 不接入；窄窗口设置仍用 Popover | 组件已实现，应用没有改用侧边抽屉；接入点见文末 |
| `ContextMenu` / `Select` | 未实现 | 不接入；记录为后续接入点 | 任务 T-044，及 M2 范围之外 |
| `Spinner` | 可用（基础实现） | 不接入；应用没有加载态 | 该基线上尚未实现，后续提交已加入，见 README 组件表；像素基线与官方弧度/周期核对仍待补 |

工作区基线在开工时执行过 `cargo check --workspace --all-targets --locked`，通过；这只能证明工程可编译，
不能证明本应用交互正确。

## 应用结构与状态模型

```text
FluentRoot
├─ 顶栏：标题、内存模式 Badge、设置 Popover（图标按钮 + Tooltip）
└─ 主体
   ├─ 左侧：便签列表（新建按钮、列表、空列表态、内存提示）
   └─ 右侧：标题 Field、操作栏（保存/取消/置顶/属性/更多/删除）、正文 Textarea、状态栏；确认以模态对话框呈现
```

- **数据**：`Vec<Note>` 保存在 `NotesApp` 内；每条便签有 `id`、`title`、`body`、`pinned`、`tone`、`updated_seq`。
  展示顺序为“置顶优先，其次最近更新”。所有修改只改内存。
- **草稿**：标题与正文各有一个跨重绘保留的 `InputState` / `TextareaState`。编辑区只在“显式载入某条便签”时调用
  `set_value`（新建、切换、取消、删除后的回退、保存并切换），主题切换、浮层开关和普通重绘不会写回输入状态。
  因此光标、选择和未保存文本在重绘后保持；`set_value` 本身会把选择重置，取消/切换后的光标位置因此不保证保留。
- **脏检查**：渲染时读取输入状态与 `editor_note` 的已保存值比较，用于“未保存”标记、取消按钮可用性和切换判断。
  输入实体的通知会驱动应用重绘，以便字数与脏标记实时更新。
- **未保存切换**：点击另一条便签或“新建”时，若当前编辑有未保存内容，不直接切换，而是弹出模态
  `Dialog`：“保存并切换（新建） / 放弃修改并切换（新建） / 留在当前”。Esc 与点击 scrim 等价于
  “留在当前”；Enter 等价于第一项“保存并…”。只有显式选择前两项才会丢弃或提交草稿。
- **保存反馈**：保存更新便签内容、更新时间和排序，并在状态栏显示带图标的“已保存：…”消息；列表标题/预览同步更新。
- **删除**：先弹出 `AlertDialog`（说明“不可撤销”“未保存修改会丢弃”）；确认后删除并选中相邻便签；删掉最后一条后显示空列表
  与空编辑页。AlertDialog 无 Esc/scrim 关闭，必须点“确认删除”或“取消”；Enter 视为确认。
- **主题**：设置浮层内的受控 Radio 切换 `FluentTheme::global(cx).with_appearance(...).install(cx)`；
  三种主题都从 token 取色，不使用硬编码颜色。

## 手工验收清单

每条都是“步骤 → 期望”。执行结果与未执行项写在[验证记录](../validation/notes-app-2026-11-03.md)，不要把本清单当成已通过。
建议窗口：默认 1180×760；窄窗口一项缩到约 520 宽；主题三项依次切换。

### A. 新建、保存与往返

1. 点击左侧“新建便签”（或空状态里的新建按钮）。
   期望：新便签成为选中项；标题输入框获得焦点；状态栏提示新建；列表出现空标题占位。
2. 输入中文和英文标题（例：`会议记录 Meeting notes`），在正文输入两段中英文。
   期望：标题/正文即时显示；状态栏字数变化；“未保存”标记出现；取消按钮由禁用变为可用。
3. 点击“保存”。
   期望：状态栏显示“已保存：会议记录 Meeting notes”；未保存标记消失；列表标题与预览更新；便签按最近更新排序。
4. 点击另一条便签，再点回刚保存的便签。
   期望：没有对话框（因为已保存）；标题与正文完整恢复；光标位于新载入文本的起点（`set_value` 语义）。

### B. 取消编辑

5. 选中一条便签，修改标题和正文，不要保存，点击“取消”。
   期望：输入框恢复该便签上次保存的标题与正文；状态栏说明已还原；未保存标记消失。
6. 在没有未保存修改时观察“取消”。
   期望：按钮为禁用外观，点击不改变任何状态。

### C. 未保存时切换 / 新建

7. 修改当前便签但不保存，点击另一条便签。
   期望：不立即切换；弹出模态对话框，明确列出目标便签；当前草稿仍在输入框中；背景被 scrim 遮挡。
8. 在对话框中选择“留在当前”（Esc 或点击 scrim 等价）。
   期望：仍在原便签，草稿与光标未丢失。
9. 再次点击另一条便签，选择“放弃修改并切换”。
   期望：目标便签载入；原便签保持上次保存内容；状态栏说明丢弃了草稿。
10. 修改后用“保存并切换”。
    期望：当前便签保存成功，再载入目标便签；保存反馈仍可见或可读。
11. 修改后点击“新建便签”。
    期望：同样先确认；确认后创建空便签，原草稿按所选动作处理。

### D. 删除与空状态

12. 点击“删除”（工具栏或“更多”菜单），观察弹出的 AlertDialog。
    期望：明确显示便签标题与“不可撤销”“未保存修改会丢弃”；有“确认删除 / 取消”。
13. 选“取消”。
    期望：便签、选中状态、草稿都不变。
14. 选“确认删除”当前便签（列表中还有其它便签）。
    期望：该便签消失；自动选中相邻便签并载入；状态栏报告删除结果。
15. 删除到只剩一条，再删除最后一条。
    期望：左侧显示空列表提示和新建入口；右侧显示空编辑页（不是空白无说明）；状态栏说明 0 条。
16. 从空状态点击“新建便签”。
    期望：恢复可用编辑流程。

### E. 置顶与菜单

17. 打开“更多”菜单（图标按钮，悬停应出现 Tooltip）。
    期望：菜单包含“置顶”勾选项、分隔线、禁用项（“移动到文件夹…”），禁用项不可点击/不可键盘激活。
18. 用鼠标移动到“置顶”，按 Enter；重新打开菜单。
    期望：列表顺序变化，置顶组在上；菜单中该项显示为勾选；状态栏有置顶反馈。
19. 用键盘 Down/Up/Home/End 移动高亮，再按 Enter/Space。
    期望：高亮行与实际激活行一致；跳过禁用行和分隔线；菜单动作后关闭并把焦点还给触发按钮。有未保存草稿时对“取消修改”重复一次：内容恢复、菜单关闭、焦点回到触发按钮。
20. 在菜单打开时按 Esc。
    期望：菜单关闭，不执行任何项，焦点回到触发按钮。

### F. 属性 Popover

21. 点击“属性”按钮。
    期望：浮层锚定在按钮下方；焦点进入浮层；面板内有可交互的 Switch 与 Radio。
22. 在浮层内切换“置顶”和“颜色标记”。
    期望：列表与编辑区标记即时更新；浮层保持打开；可继续用 Tab 在面板内移动（陷阱内循环）。
23. 点击面板外的列表/编辑区。
    期望：浮层关闭；点击落点按正常控件行为处理；关闭后若焦点原在面板内，焦点归还触发按钮。
24. 按 Esc 关闭浮层。
    期望：仅关闭浮层，不触发其它动作；焦点回到触发按钮。

### G. 设置与受控 / 非受控

25. 打开设置（顶栏齿轮图标，悬停有 Tooltip）。
    期望：面板包含主题 Radio（light/dark/high-contrast）、受控“显示列表字数”Checkbox、受控“紧凑列表”Switch，
    以及明确标注的非受控 Checkbox / Switch 示例。
26. 在设置打开时切换三个主题。
    期望：整个窗口颜色/边框/焦点样式同步改变；面板保持打开；控件的选中状态与主题一致。
27. 切换“显示列表字数”和“紧凑列表”。
    期望：列表行信息/密度立即变化；重绘、主题切换和浮层开关后保持（受控值来自应用状态）。
28. 切换非受控示例，然后切换主题、开关浮层、触发重绘。
    期望：非受控控件保持用户选择（组件 keyed state），不会因重绘回到 `default_*`。

### H. 键盘与焦点

29. 从标题输入框开始连续按 Tab / Shift+Tab。
    期望：顺序可预期（标题 → 正文 → 操作按钮/图标按钮 → 列表/设置等），不跳入浮层背后；Shift+Tab 可反向回到起点。
30. 在 Popover 打开时连续 Tab。
    期望：焦点逐项移动，在末项按 Tab 回到首项、在首项按 Shift+Tab 回到末项；不出现无视觉焦点的面板容器停靠点，也不逃到背景页面。
31. 在菜单中使用方向键、Home/End、Enter/Space、Esc。
    期望：见 E 组；菜单打开时字符键不应被吞到页面其它控件。
32. 聚焦 Checkbox / Switch / Radio 后按 Space / Enter。
    期望：切换一次，不重复触发；禁用控件不响应。

### I. 文本编辑细节

33. 在标题/正文中用鼠标选择一段文字，再用方向键、Home/End 移动光标，然后输入替换。
    期望：选择、光标与插入行为由输入引擎处理；应用重绘不跳光标。
34. 用中文输入法组合输入标题与正文（先拼音，再上屏）。
    期望：组合过程不丢字、不跳光标；上屏后保存的内容与界面一致。
35. 在编辑过程中切换主题、打开/关闭设置或属性浮层、改变列表密度。
    期望：草稿文本、光标/选择、未保存标记和控件状态保持；不出现重复保存或重复切换。

### J. 极值与视觉

36. 保存空标题、空正文。
    期望：列表显示“无标题便签 / （无正文）”；编辑页不回填占位文字；状态栏提示已保存。
37. 输入很长的标题（例 120 个字符）和很长的正文（多屏）。
    期望：列表标题单行截断且不撑破侧栏；编辑标题仍在单行输入框内滚动；正文区域可用键盘/光标滚动（本版鼠标滚轮不生效，见已知限制），不挤压操作栏。
38. 把窗口缩到约 520 宽，重复 A/D/E/F 的主要操作。
    期望：侧栏有最小/最大宽度，编辑区仍可用；操作栏可换行；浮层仍在视口内。
39. 在 light / dark / high-contrast 三种主题下重复 36–38。
    期望：文字、边框、禁用态和焦点态可辨；高对比度不出现低对比装饰文字。
40. 在系统 100% 与更高 DPI（或缩放）下启动并检查边界、1px 描边和文本裁切。
    期望：布局按逻辑像素稳定，不出现半像素模糊或控件重叠；此项需要实际显示器环境。

## 已知限制

- **内存数据**：关闭窗口或进程后全部丢失；不写文件、不联网、不做恢复。
- **Dialog**：删除与未保存切换已用模态对话框；对话框打开期间背景被 scrim 遮挡不可交互，Tab 在卡片内循环。`Role` 设在宿主内层，是否到达 accesskit 树未验证。
- **没有 ContextMenu / Select**：设置用 Popover，属性编辑用 Popover；未提供右键菜单或下拉选择。`Tabs` 与 `Sheet` 组件已实现，但本应用尚未改用（设置仍是单列面板，窄窗口仍用顶栏 Popover）。
- **菜单**：子菜单未实现；item 激活后不会自动关闭，应用的动作回调显式清 `menu_open`（“取消修改”已覆盖）；禁用状态不通过 accesskit 暴露（本版 GPUI 没有可用 API）。
- **Popover**：边缘使用连续限位而不是上下翻转；面板大于视口时可能无法完整容纳；打开时焦点落在面板容器，不自动进入第一个控件，但容器本身不是 Tab 停靠点，Tab 只在控件之间循环；
  Esc 只在焦点位于浮层内时生效（本应用为两个浮层都传了 `track_focus`）。
- **Tooltip**：由指针悬停触发；键盘聚焦不显示；翻转/定位仍只有有限的自动测试，需要原生窗口复核。
- **Radio 组**：Radio 支持 Tab 到达与 Enter/Space 切换，但没有组内方向键；主题选择用 Tab 或指针切换。
- **未保存状态**：标题栏用文本显示“编辑中 · 未保存/已保存”。虽然 Warning Badge 的前景对比缺陷已修复（见[修复记录](../validation/badge-contrast-2026-11-03.md)），应用仍保留文本表达：不以单一颜色徽标作为唯一状态信号。
- **长正文滚动**：本版 GPUI 快照的 Textarea 不处理鼠标滚轮；光标/键盘移动会把视图带到目标位置并显示滚动条。应用不包一层假滚动容器来掩盖该缺口。
- **无障碍**：无 live region，保存/删除结果不会主动播报；菜单位置与当前项不通过 `aria-activedescendant` 表达；
  禁用 MenuItem 的 accesskit 状态缺失。真实屏幕阅读器未验证。
- **输入法**：已验证字符插入与粘贴的中英文内容；真实 IME 组合输入（候选窗、组合中重绘）仍需在原生窗口手工验证。
- **视觉**：没有像素基线；本应用不进 Gallery 的基线矩阵。已在 Windows 150% DPI 的真实窗口检查 light / dark / high-contrast 与约 520 逻辑像素宽的窄窗口；100% 和其他缩放、其他平台未验证。
- **未保存草稿**：草稿只存在于当前编辑器的两个输入实体中，不在每条便签上分别保存；“留在当前”以外的选择会丢弃或提交它。
  切换时没有自动保存，避免把未确认的输入当成已保存内容。
