# 菜单打开动画：实测官方是原地淡入

日期：2026-11-04。基线：HEAD `e2501be` + 未提交改动。

## 怎么量的

参考录屏是官方文档页的菜单示例。用 `ffmpeg` 按 60fps 抽帧，对面板与页面深色横幅重叠的区域做像素测量：

| 量 | 结果 |
|---|---|
| 面板宽度 / 左右边界 / 上边缘 | 淡入全程恒定（206px，x 522–728） |
| 面板内平均亮度 | 36 → 109 → 148 → 178 → 199 → 215 → 227 → 236 → 242 → 247 → 249 → 252 |
| 换算成不透明度 | 0 → 0.34 → 0.52 → 0.66 → 0.76 → 0.83 → 0.89 → 0.93 → 0.95 → 0.98 → 0.99 → 1.0 |
| 时长 | 约 350ms，强减速（前 100ms 到 76%，之后长尾） |
| 关闭 | 一帧内完全消失，无淡出 |

结论：官方是**原地淡入**——尺寸与位置自始至终不变，只有不透明度在升。此前按「高度从 0 长到内容高度」实现的方向是错的，已废弃。

## 实现

- `fluent_core::spec::motion` 新增 `menu_reveal_opacity(progress) = 1 - (1 - p)^4` 与
  `DURATION_MENU_REVEAL = 350ms`
- `Menu` 在 `MenuDropdown` 打开时读取递增的「代号」，按 `now - opened_at` 计算进度并施加
  `opacity`，未走完时 `request_animation_frame()`
- 独立摆在页面里的菜单不播（`reveal` 为 `None`），`reduce_motion` 时直接满不透明度

## 回归证据

| 测试 | 断言 |
|---|---|
| `spec::motion::the_menu_reveal_matches_the_recorded_fade` | 5 个实测样本，容差 0.05；两端必须为 0 / 1 |
| `spec::motion::the_menu_reveal_only_rises` | 20 段单调不降 |
| `menu::reveal_tests::the_menu_fades_in_at_its_final_size` | 首帧 alpha ≈ 0 且尺寸已是终态；120ms 时 0 < alpha < 0.99；结束 alpha = 1.0；高度全程不变 |

把不透明度强制为 1（等于没有动画）后，控件级测试失败：

```text
the menu starts transparent, got alpha 1
```

## 局限

- 官方数值来自录屏像素测量（30fps 源、60fps 抽帧），时长精度约 ±30ms；曲线用四分 ease-out 近似，**不是官方源码数值**。
- 本环境外网抓取被拦，只确认 `@fluentui/react-menu` 包内存在 `MenuSurfaceMotion` 模块，未读到实现正文。
- 未做真实窗口目视；测试窗口用绘制数据（quad 的 alpha）断言。

## 追加：还有向下归位的位移

第一轮测量只用「宽度」和「包围盒」，得出「位置不变」的结论是**错的**：包围盒在低透明度时只能检出文字和阴影，会把面板量小，看起来像"在长"。改用**行剖面互相关**（把早期帧的文字行分布与终帧比对，求最佳垂直位移）：

| 帧 | t | 不透明度 | 最佳垂直位移 | 相关系数 |
|---|---|---|---|---|
| 104 | 1.73 | 0.76 | +4 px | 0.30 |
| 106 | 1.77 | 0.83 | +2 px | 0.46 |
| 110 | 1.83 | 0.93 | +1 px | 0.80 |
| 116 | 1.93 | 0.98 | 0 px | 0.98 |
| 124 | 2.07 | 1.00 | 0 px | 1.00 |

`+N` 表示把早期帧**下移 N 像素**才能与终帧对齐，即内容在淡入过程中向下归位约 4px。低透明度帧的相关性太低（0.24–0.30），所以只有 4px 这个量级可信，后面的 ±1px 在噪声内。

据此新增 `spec::motion::menu_reveal_offset(progress) = -4 * (1 - progress)`，`Menu` 在淡入时同时施加 `.relative().top(...)`。

回归证据：把位移强制为 0 后，控件级测试失败：

```text
the menu must start higher and settle down: first 76, settled 76
```

曲线是线性归位，**没有**从录屏反推出精确缓动——4px 的位移在 30fps 下不足以拟合曲线，这是本轮明确的未知项。

## 修正：位移与淡入必须同步收尾

先前实现是「透明度四分缓动 + 位移线性 350ms」，观感变成**先显现、再滑动**：透明度前 100ms 就到 76%，而线性位移此时只走完 28%。

改为位移复用同一条曲线：`menu_reveal_offset(p) = -4 * (1 - menu_reveal_opacity(p))`，两者同时到达终点、形状一致。

回归证据：把位移改回线性后，控件级测试失败：

```text
movement and fade must share a curve: 0.625 of the offset left vs 0.186 of the fade left
```

同时新增断言：任一中途帧上「剩余位移比例」与「剩余不透明度比例」之差必须小于 0.1（容差用于吸收绘制的像素吸附）。
