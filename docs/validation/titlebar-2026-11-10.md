## 回归测试与首次失败

- 初次编译修正了测试适配本版 GPUI 的细节（listener 不可直接 clone、WindowHandle::read 返回 Result、Quad 使用 ScaledPixels）；相关原因已定位后才继续验证。
- 将虚拟菜单换成真实 Popover 后，测试首次失败是夹具将 absolute 位置放在 trigger 子元素、实际测量到 anchor 的流布局边界；改为定位 Popover 外层，并断言 popup 确实覆盖关闭按钮，未放宽断言或改变产品定位算法。
- 原生验收首次在最大化还原后立即取到旧 client size；改为每次轮询重新取 client rectangle 与实际 caption hit，等待首个有效状态，不以延时绕过产品缺陷。
- 原生夹具最初用 F6 解除关闭否决，但该测试动作未到达监听器；未将其记成关闭流程通过。最终夹具改为确定性的“首次否决、第二次允许”，直接验证同一个应用关闭 hook 的两种结果。
- 5 项定向破坏全部使对应测试失败（exit 101 且实际 `test result: FAILED`，不是编译错误）：恢复 native 手动 click、将 caption 优先级降到 0、将真实 Popover 优先级降到 0、把 pressed 颜色退回 hover、绕过 fallback 关闭否决。见[结果](../../target/titlebar-mutations.json)与[运行摘要](../../target/titlebar-mutations-run.log)。每项变更前保留源码，恢复时检查文件仍等于本项 mutant；检测外部改动则拒绝覆盖。全部恢复后重跑最终 workspace 检查通过。

## 补充：按用户参考图调整轻微圆角

### 第一轮：只加圆角

- 将最大化的直角条带轮廓改为 outline quad，`glyph_corner_radius` 基准取 1.5 逻辑像素；还原图形的前后两层同步使用圆角。后层只裁出可见的顶部和右侧，不用背景填充遮盖，因此继续适配主题与 hover。10px 图形盒、线宽、按钮尺寸、原生命中与关闭路径未改变。
- 用户随后指出"还是没那么圆润"。把官方参考图与自绘结果对齐成 15×15 像素块逐格比较后确认：直边厚度接近，但角部覆盖差异明显——参考图为 `1/7`（角格 1/9、次格 7/9），我们为 `2/9` 与 `9/9`，即角部更方、更重。
- 原因是 `paint_quad` 会把边框宽度按设备像素取整：150% 下 1 DIP 描边变成 2 设备像素，1.5 DIP 半径变成 2 设备像素，内圆角正好归零。仅取消组件内的取整不够，GPUI 在 `paint_quad` 内部仍会再取一次。
- 回归测试 `window_outline_keeps_an_inner_corner_and_cuts_its_square_corners` 在修复前失败并输出 `Maximize inner corner became square at 1.5x: radius=2, stroke=2`，复现了该缺陷。

### 第二轮：改用矢量描边并标定半径

- 最大化/还原轮廓改为 `PathBuilder::stroke` + `arc_to` 的圆角矩形路径，绕开边框取整；描边宽度 1 DIP、半径进 spec 作为 `glyph_corner_radius` 并保留分数设备像素。
- 半径用截图测量标定，而不是估一个值：150% 原生截图中，1.5 DIP 角部为 `2/9` 与 `9/9`（偏方），2.0 DIP 为 `0/9` 与 `5/9`（略偏圆），1.75 DIP 为 `0–1/9` 与 `7/9`，与参考图的 `1/9` 和 `7/9` 基本一致。最终取 1.75 DIP。
- 回归测试改为几何断言：`glyph_corner_radius > glyph_stroke_width`（内圆角必须存在），并且描边的任一顶点不得落在方角区域（`0.25 × 半径` 见方），半径归零或内圆角被吃掉时失败；同时断言描边仍撑满 10px ink box。测试平台无法提供 path 的绘制访问器，因此改为直接检查构建出的路径顶点，而不是退化成只断言 spec 常量。
- 本次 6 项标题栏测试通过；完整 workspace 检查见下。

## 补充：标题栏前置图标槽与窗口图标

用户询问窗口图标是否有预留。核对结论：此前没有——`.icon()` 只在给定 Fluent 字形时绘制，未设时标题直接从 12 DIP 边距开始，且 `window_options` 未设置 `WindowOptions::icon`。

本轮按批准的三点方案实现：

1. **固定图标槽**：标题前 16 DIP 见方、后接 8 DIP 间距；`icon`（Fluent 字形）、`logo` / `logo_bytes`（位图）与 `icon_slot()`（空槽）共用同一槽位。默认仍不预留，只有显式 `icon_slot()` 才在无图时占位。
2. **位图入口**：`logo(Arc<gpui::Image>)` 与 `logo_bytes(ImageFormat, Vec<u8>)`，走 `ImageSource::Image`，由 GPUI 在 UI 线程外解码；绘制用默认 `ObjectFit::Contain` 缩进槽内。为此 `fluent-components` 增加 `image` 依赖（`WindowOptions::icon` 的类型就来自它，本已在依赖树中），`Cargo.lock` 只多一行 `image`。
3. **系统窗口图标**：新增 `TitleBar::window_options_with_icon(title, Arc<image::RgbaImage>)`。

**平台限制（源码核对，非猜测）**：本版 GPUI 中只有 X11 读取 `params.icon`（`gpui-pre-linux/src/linux/x11/window.rs:803` 写入 `_NET_WM_ICON`）；Windows 的窗口类图标来自可执行文件资源（`gpui-pre-windows/src/platform.rs:1638` 的 `load_icon()`），macOS 来自应用包，二者都忽略该字段。因此 Windows/macOS 上"任务栏与标题栏同源"**不能**只靠这个字段，任务栏图标仍需打包资源；标题栏 logo 在各平台都正常绘制。已在 API 文档与子系统说明中写明，未宣称跨平台生效。
