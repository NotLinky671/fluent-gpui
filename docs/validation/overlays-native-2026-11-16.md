# 浮层的原生验收（Windows，2026-11-16）

T-052 剩下的两条交付都是"只能在真实窗口里看"的事：面板在真实窗口中的命中归属、
真实事件顺序，以及 Tooltip 的 hover/隐藏/翻转/滚动跟随；还有子菜单的逐层命中与
300ms 悬停手感。此前这些只有"测试里用 canvas 与垫底元素近似"或干脆没有。

这次用真实输入队列把它们跑了一遍，并把每一步的判据落在像素与探针日志上。

## 环境

| 项 | 值 |
|---|---|
| 系统 | Windows 11 25H2，build 26200 |
| 缩放 | 150%（逻辑 900×620 的探针窗口，客户区物理 1350×930） |
| 构建 | `cargo build -p fluent-gallery --example overlays_probe --locked`，debug |
| 输入 | `SetCursorPos` + `mouse_event`（左键、滚轮）+ `keybd_event`（Escape） |
| 取像素 | `PIL.ImageGrab` 抓客户区，坐标按 `GetDpiForWindow / 96` 换算 |
| 窗口 | `WindowOptions` 默认（无自绘标题栏），客户区原点用 `ClientToScreen` 读 |

## 怎么跑

```powershell
cargo build -p fluent-gallery --example overlays_probe --locked
python scripts/verify-overlays-windows.py              # 四类一起
python scripts/verify-overlays-windows.py --only menu   # 只跑一类
```

退出码非 0 表示有检查失败，结果写在 `target/overlays-native.json`，截图写在
`target/overlays-<mode>-<name>.png`。探针在启动时打印 `anchor` 行，脚本据此定位，
不把坐标写死在两个地方。

## 与文档不一致、需要更正的地方

**面板会被滚动容器裁掉。** `docs/subsystems/overlays.md` 原来写"deferred 路径让面板
脱离普通滚动内容的裁剪"。实测：触发滚出容器后（三格滚轮），面板与触发一起消失，
而弹层状态仍是打开（没有关闭回调）；把滚轮反向滚回，面板重新出现（顶边 196.0）。
也就是说 deferred 解决的是绘制顺序，不解决祖先容器的裁剪。文档已按实测改写；原因
（是触发边界不再上报，还是面板被裁剪掩膜切掉）还没有定位，不写成结论。

## 写脚本时踩到的四件事（都不是产品缺陷）

1. 探针最开始用受控 `Popover.open(...)` + `MenuDropdown.open(...)`：受控模式没有内置
   toggle，点击什么也不会发生。改成 `default_open` 后立刻正常——这正好复述了
   [受控 Popover 的触发器语义](../subsystems/overlays.md)那一条。
2. 以为 tooltip 是深色面，用"找暗块"去测：抓到的其实是按钮文字。截图看到 tooltip 是
   浅色面，改为"在深色页面上找亮面"，并且用**面积**过滤字形（≥400 物理像素）。
3. 第四行的中心原来是手写常量 `262`，实际是 `280`：菜单面板顶部由触发底边 + 间隙决
   定，行高 32、间隙 2、内边距 4。改成从测得的触发位置算出来。
4. 滚动模式的触发锚点原来也写错（`180,138` 是容器左上角附近，真实位置是 `200,214`，
   第三行填充分隔之后），改了锚点才点得到。

## 仍未验证

- 100% 与 200% 缩放、多显示器跨屏拖动；本轮只有 150%。
- 键盘触发的 Tooltip（聚焦显示）与"滚动时 tooltip 跟随"这一条没有单独跑。
- 三层及以上子菜单链、子菜单在窗口右边缘的翻折，只有实测到的一层子菜单。
- Sheet 的原生滑入/滑出与关闭后的焦点归还时序（本轮未涉及）。
- 面板打开期间改变窗口大小、超长内容（菜单已有高度上限，但浮层没有等价上限）。
- macOS 与 Linux：本脚本只用 Win32 输入与 `ImageGrab`。
