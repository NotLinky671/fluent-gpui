# 标题栏手势验收（2026-11-16）

`scripts/verify-titlebar-windows.py` 证明的是窗口消息：命中区域、caption 按钮、模态与关闭否决。
它证明不了人手的动作——按标题拖动、双击缩放、靠边吸附、抓角落改尺寸。本轮补上这一段，用的是真实输入队列而不是我们自己记录的状态。

## 环境

| 项目 | 值 |
| --- | --- |
| 系统 | Windows 11 25H2 build 26200 |
| 工作区（物理像素） | `(0, 72)-(2560, 1600)` |
| 窗口缩放 | 150%（`GetDpiForWindow` / 96 = 1.5） |
| 被测程序 | `target/debug/fluent-gallery.exe`，`FLUENT_GALLERY_SECTION=backdrop` |
| 输入 | `SetCursorPos` + `mouse_event`，`keybd_event` 合成 `Win`+方向键 |
| 测量 | `GetWindowRect`、`IsZoomed`、`IsIconic`，截图用 Pillow `ImageGrab` |

脚本按"每个手势之前先把窗口恢复到普通状态并重新读矩形"的顺序执行，因为上一次手势留下的最大化或吸附状态会让下一次的坐标失去意义。

## 命令

```powershell
cargo build -p fluent-gallery --locked
python scripts/verify-titlebar-gestures.py
```

退出码 0 表示全部手势通过；报告写在 `target/titlebar-gestures.json`。

## 结果

| 手势 | 观测 | 结论 |
| --- | --- | --- |
| 按住标题条向下拖 90px | `(594,423,1966,1394)` → `(594,333,1966,1304)`，纵向 −90、横向 0 | 窗口跟随指针，没有横向抖动 |
| 双击标题条 | `IsZoomed = True`，矩形 `(-11,61,2571,1611)` | 最大化覆盖整个工作区（两侧各超出 11px 是隐身边框） |
| 再次双击 | 回到 `(594,333,1966,1304)` | 还原到拖动之后的尺寸 |
| `Win`+`←` | `(-9,72,1289,1609)` | 吸附左半屏，顶边贴工作区 |
| `Win`+`→` | `(1271,72,2569,1609)` | 吸附右半屏，右边贴屏幕边缘 |
| 拖右下角 +120/+80 | 宽高各增 120 与 80 | 角部缩放有效，两轴同时生效 |
| 移动多轮后点最小化 | 命中点 `(960,132)`，`IsIconic = True` | caption 按钮没有被标题拖拽区吞掉 |

最大化状态截图：`target/titlebar-maximized.png`（2571×1550，工作区尺寸）。
图中可见自绘标题栏（图标 + `Fluent Gallery`、右侧最小化/最大化/关闭）、最大化后四角为直角、没有系统标题栏残留。

## 第一轮失败是脚本的问题，不是窗口的问题

第一版脚本报了 5 条失败，逐条查下来都是测量代码的错，记录在此以免下次重复：

- 双击还原用了**最大化之前**的标题坐标——窗口已经移到别处，那一下落在内容区。改为每次双击前重新取矩形。
- `Win`+`→` 在"左吸附"状态之后的一次合击里没有生效，但单独从普通窗口发同一个组合键立刻吸附到右半屏；把两个方向拆成各自从普通状态出发的一次手势后稳定通过。
- 角部缩放选的是吸附后的右下角 `(1288,1608)`，而工作区到 `1600` 为止，纵向根本不在屏幕上——宽度涨了 110、高度 0。改为先把窗口拖到工作区左上角附近再抓角。
- 最小化点错成了最大化按钮（`right - 69`），改成按 46 DIP 按钮的几何算：`right - 115 * scale`。

## 仍未验证

- 最大化窗口的圆角与阴影观感、caption 悬停/按下的具体色值：截图只证明几何，色值要靠眼睛或像素基线。
- 高对比度、窗口失活时的 caption 观感。
- macOS（红绿灯位置）与 Linux（装饰分支）的真机行为。
- 跨显示器拖动时的缩放切换。
