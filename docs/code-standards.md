# 工程规范与组件交付清单

目标：让“实现存在”“测试通过”“真实使用正常”各有证据，不用一份绿灯替代另一份。
适用于本项目的 Rust / GPUI 组件；不照搬浏览器引擎、Go 或其他项目的发布流程。

## 修改前

1. 读报告到最后一条反馈，确认任务未暂停；记录原始输入、平台、缩放、主题和操作路径。
2. 在报告所用的原生窗口中复现可见问题；无该环境时明确说明，不以相似样例代替。
3. 查同类实现及下游：选择控件、输入控件、浮层分别成组；共享 token、theme、motion 的改动检查所有使用者。
4. 一次改动一个目标。检查工作区，避免覆盖其他人的文件；并行工作用独立 worktree，不共享可变日志。

## 实现规则

- **分层**：spec 负责可单测的样式决策，组件负责渲染与交互。沿用精确锁定的 GPUI 栈，不引入第二套 GPUI 类型。
- **状态归属**：显式参数优先于默认值；受控组件由调用方持有状态；非受控默认值只作初始化，不因重绘重置用户操作。
- **错误处理**：读、解析或资源加载失败是未知或错误，不默认为成功；若使用最后一次有效值，要说明该策略并测试失败路径。
- **同类检查**：修复一处时列出同类实现，说明需改、不受影响或待办的依据；留下的问题必须可追踪。
- **生命周期**：测试启动的子进程、任务和窗口在失败、超时及正常结束时都要清理。不要无限等待子进程。
- **时序**：等待被测状态或推进可控帧，不用固定休眠证明交互完成。定位测试检查首次绘制和事件后的首帧，不能靠后续补帧掩盖错误。
- **热路径**：render、prepaint、paint 和动画每帧执行；新增工作按组件数量与大输入评估，避免每帧重复 IO、解析或扫描。
- **生成物**：修改输入快照或生成器后重新生成，再执行对应 `--check`；不直接修补生成结果。

## 子系统设计与审查

- 修改或审查前，从[子系统导航](subsystems/README.md)选择相关职责，阅读专题并核对链接的源码与测试；不要求每次通读所有子系统，也不把文档当作无需核实的真值。
- 描述“修改前 → 修改后”的用户/调用方可观察行为、受影响入口及兼容性。仅列文件名或写“修复组件”不够；纯文档改动可明确说明运行时行为不变。
- 改变状态归属、实际调用路径、布局/绘制阶段、默认值、回调时机、公开 API 或关键验证方法时，同一改动同步导航/专题和相关公开说明；无需更新时在 PR 中给出理由。
- 审查要沿实际运行路径检查读写双方与同类调用者，确认旧测试仍在检查承诺；新接线不等于行为验证，视觉遮挡不等于事件隔离，限位不等于翻转。
- 设计说明记录职责、路径、约束和验证入口，不复制源码、完成率或最新测试数字；运行结果与环境留在验证记录。纯重命名只需修复受影响的链接/符号，不机械增加设计文档。
- 非本会话改变 HEAD、暂存区或目标文件时暂停相关写入并确认归属；有提交授权时逐项检查暂存内容，不将其他目标或未经复核的中间文档一起提交。

## 组件交付清单

每项记录为“通过 / 失败 / 未验证 / 不适用”，并附证据或理由。源码存在、任务完成和历史记录都不自动等于本次通过。

- [ ] **样式**：spec 覆盖受影响的尺寸、外观、主题及状态优先级，包含 disabled 与边界输入。
- [ ] **交互**：验证适用的指针、键盘、焦点、回调次数、受控/非受控、重绘后状态保持；涉及语义时检查 AccessKit role/state。
- [ ] **原生效果**：在受影响平台的真实窗口检查；按风险覆盖 light/dark/high-contrast、窄窗口、长文本、中英文、DPI 与 reduced motion。输入法改动使用真实 IME。
- [ ] **回归证据**：修复应有能在旧实现或定向破坏后失败的测试；写明破坏方式与结果，没做就标未验证。
- [ ] **同类与文档**：列出同类实现检查结果；同步中英文 README、公开 API、限制和本地任务记录（若存在）。
- [ ] **交付记录**：使用 [PR 模板](../.github/pull_request_template.md)记录最终代码版本、环境、命令、结果、日志和未验证项。

### 三层验证各自证明什么

| 层次 | 证明范围 | 不能替代 |
|---|---|---|
| spec 单测 | token 映射、尺寸、颜色、状态优先级等计算 | 事件接线、真实布局、绘制和输入法 |
| GPUI 行为测试 | 事件、状态、焦点、布局时序和裁剪等被测行为 | 原生平台集成、字体栅格与 GPU 输出 |
| 原生窗口/像素检查 | 指定环境的实际效果，或相对基线的视觉回归 | 未覆盖状态、键盘与无障碍语义的完整正确性 |

## 验证矩阵

按影响范围选择，不对纯文档改动强行跑 GPU 测试，也不以局部测试代替共享逻辑的全套检查。

| 改动 | 最低验证范围 |
|---|---|
| 纯文档/模板 | 检查链接、命令与源码一致，中英文及状态说明同步；不声称运行了代码测试 |
| spec / 组件行为 / 公共 API | 定向测试 + 下列 workspace 检查；增加受影响的行为测试；可见变化还需原生/视觉验证 |
| token / theme / motion / 共用布局 | workspace 检查 + 所有受影响组件的主题、状态、缩放和视觉检查 |
| 生成器 / 输入快照 | 对应生成物 `--check` + workspace 检查；检查生成差异与上游版本来源 |
| GPUI 升级 / 平台代码 / 发布候选 | 三平台 CI + 受影响平台真实窗口验证；发布前核实最终版本的产物，而不是只看标签 |

代码改动的 workspace 检查（覆盖当前 CI 的主要检查，本地 Cargo 命令额外使用 `--locked`；生成物检查也覆盖未直接改动的依赖关系）：

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo doc --workspace --no-deps --locked
cargo deny check
cargo xtask gen-tokens --check
cargo xtask gen-icons --check
```

`cargo deny check` 可能更新安全公告数据，需要按环境联网；离线运行必须注明数据新鲜度限制。
普通测试使用本地快照和 fake，不依赖外部服务。生成快照、真实平台验证与审计是独立活动。
本地任务索引存在时可额外运行 `cargo xtask tasks --check`；它依赖不随 clone 分发的本地任务目录，不是共享 CI 的现有门槛。

### 当前视觉验证边界

- [CI](../.github/workflows/ci.yml)运行三平台普通测试及 Windows 启动 smoke；**没有运行像素比对**。
- [像素测试](../crates/fluent-gallery/tests/baselines.rs)需要 `screenshot` feature 和可用 GPU surface，目前只在本地运行。
- 已提交 15 张 Windows / light 基线；当前基线目录仅按 OS 区分，没有按 DPI/字体/渲染器隔离，其他环境不能直接套用。
- 当前夹具没有覆盖 dark/high-contrast、hover/focus/pressed/disabled。spec 单测不能替代这些状态的原生视觉验证。

在具备相应环境时运行：

```text
cargo test -p fluent-gallery --features screenshot --test baselines --locked
```

只有**有意接受视觉变化**时才设置 `FLUENT_BASELINE_UPDATE=1`，审查 actual/diff 和基线差异，然后取消更新模式重跑。不要扩大容差或重录基线来掩盖未知原因的红灯。
固定等待后的截图与限时启动 smoke 仅是有限检查，不是“布局已稳定”或“交互全部正确”的证明。

## 结果与交付

- 记录完整运行结束后的结果。指明基准 SHA，以及工作区未提交改动（或被测提交）；变基、合并、继续修改后重新判断哪些检查失效。
- 保留完整日志到失败原因明确；不要只保存末尾摘要。重型全套检查串行执行，不互删缓存或日志。
- 红灯先查原因；“主分支也失败”“单独运行通过”都不是豁免。无法本次修复时，给出 issue 或版本控制内的记录、负责人、输出和阻塞影响。
- 被取消、超时、没运行和旧代码上的绿灯均不计为最终验证。明确区分实现完成、验证通过、发布和用户确认。
- 本地 `plan/`、`task/` 只作补充；长期规则、公开限制与未解决风险要进入版本控制，便于新 clone 和其他会话复现。
